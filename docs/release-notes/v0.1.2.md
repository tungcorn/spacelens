SpaceLens v0.1.2 is the first normal (non-prerelease) GitHub Release.
Binaries remain unsigned. The version is still semantically pre-1.0.

v0.1.0 and v0.1.1 stay published and immutable. Their tags, zips, and
npm `@tungcorn/spacelens@0.1.1` are not replaced.

## Why this release

Since v0.1.1 the product gained Maintenance V2, a public npm install
channel, and a verified release pipeline. This tag is the first
publication of that work.

## Highlights

- Human-authorized Recycle Bin maintenance is V2: durable operation IDs,
  Attempting-before-Shell checkpoints, crash/restart Uncertain
  reconciliation, a 2-minute prepared-plan expiry, and inspection-only
  Maintenance History. Mutation stays GUI-only file-to-Recycle-Bin.
- `@tungcorn/spacelens@0.1.2` is the npm channel for this unified
  archive. Node launches the native binaries; it is not a Node SDK.
- Release Automation V2: `workflow_dispatch` on `main` creates an
  annotated tag and a latest GitHub Release only after CI and
  distribution gates. npm Trusted Publishing stays in
  `npm-publish.yml` (OIDC, no `NPM_TOKEN`).
- CLI still reports `filesystem_mutation: false`.
- Same MIT project license and Qt LGPL corresponding-source offer.

## Requirements

- Windows 10/11 x64
- [Microsoft Visual C++ Redistributable (x64)](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)
- Qt 6.8.3 runtime is bundled in the unified archive only
- Binaries are unsigned. Verify the zip hashes before use.

## Safety

The CLI cannot delete, recycle, restore, move, or declare locations.
Recycle Bin maintenance stays in the GUI and requires explicit human
authorization. SpaceLens does not write the NTFS USN journal.
